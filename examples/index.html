interstage

interstage lets tsc and your editor read a .wgsl file as the TypeGPU module it becomes. It is a TypeScript 7.1 content mapper and a 30-line Vite plugin, about 2,000 lines in all.

npm Source on GitHub Set it up Demos

It only translates the shader's declarations into TypeGPU calls. TypeGPU builds and runs the pipelines, the shaders stay plain WGSL, and the optional shader check is Tint's. Content mappers are new in a TypeScript beta, so treat this as an experiment.

Problems

    All of it runs in your browser. interstage's compiler writes "what tsc reads" on every keystroke, your browser's WGSL compiler checks the shader, TypeScript checks main.ts in a worker, and TypeGPU draws the lamp. That TypeScript is version 6, the last one written in JavaScript; in a project, tsc 7 gets the same module from the content mapper. Hover a name to see its type, and Ctrl- or Cmd-click one in main.ts to jump to where it is declared.

    Set it up

    1. Install interstage next to TypeScript 7.1 and TypeGPU.

      pnpm add -D interstage typescript@beta
pnpm add typegpu

    2. Register the content mapper in tsconfig.json. validate is optional and needs the webgpu package (pnpm add -D webgpu).

      {
  "compilerOptions": { "skipLibCheck": true },
  "contentMappers": [
    { "package": "interstage", "extensions": [".wgsl"], "options": { "validate": true } }
  ]
}

    3. Let Vite load .wgsl files as modules.

      import interstage from 'interstage/vite'

export default defineConfig({ plugins: [interstage()] })

    4. Type-check with permission to run the mapper. In VS Code, the TypeScript 7 extension does the same in trusted workspaces.

      tsc --noEmit --runExternalCode

    Limits

    • WGSL files can't import each other. A struct that two shaders share is written in both.
    • override declarations aren't supported. Use const.
    • A runtime-sized array works as a whole storage binding, not as the last member of a struct.
    • TypeGPU has only square f32 matrices, so interstage reports mat2x3f and f16 matrices.
    • Content mappers arrived in TypeScript 7.1, which is in beta, and their protocol may still change.

    Demos

    These are TypeGPU demos. Each one imports its shaders as .wgsl files through interstage, and that import is all interstage does in them. The simulations, the rendering and the input handling are TypeGPU and browser code, which the drawer on each demo shows next to the shaders.

    • Slime

      Hundreds of thousands of agents lay and follow trails in three competing species.

      interstage declares the shader's Params struct, so the sliders can only write fields it has.

    • Ink

      Stable fluids with vorticity confinement. Drag through the water to stir it.

      Nine passes share one bind group layout. interstage writes it from the shader's @group(1), and TypeGPU's types check each buffer bound to it.

    • Sculpture

      A gyroid lattice and three orbiting drops, raymarched with soft shadows.

      One fragment shader with one uniform struct, Scene, which TypeScript fills in by field name.

    • Atlas

      An endless topographic map. Drag to travel, scroll to zoom.

      The map is a TypeGPU shader written in TypeScript. It calls elevation() from atlas.wgsl, with the argument types interstage declares.

    • Postcard

      A working HTML form, drawn into a WebGPU texture with Chrome's experimental HTML-in-Canvas API, then rippled, hung as cloth or blown away as dust. It needs a Chrome flag, which the page names.

      Six small shaders, each a .wgsl file typed by interstage. The clever part is Chrome's, which keeps the drawn form clickable.
